# pancad.ai v3 網站規劃 —「一個故事，兩個入口」

> 打破 v1/v2 的「單頁型錄」思維：不再用一頁往下滾的公司簡介同時服務所有人。
> v3 = 敘事流（提案 A）× 雙入口分流（提案 B）混搭。
> 日期：2026-08-11 ｜ 狀態：待確認後動工

---

## 0. 對 v1/v2 的根本診斷（v3 要解決的問題）

1. **兩種客戶共用一條動線**：家屬想看「早發現能活下來」，醫院採購想看「92.1% 敏感度、法規字號、導入方案」— 決策路徑不同，卻共用同一個單頁型錄。
2. **產品被描述、未被體驗**：整站用文字說 AI 多強，但醫療 AI 最有說服力的是「親眼看到 AI 圈出病灶」。
3. **情感與證據互相稀釋**：溫暖故事與臨床數據夾雜，兩邊都不夠深。

v3 答案：**首頁是分流點，不是型錄。** 兩條軌道各說各話，各取所需。

## 1. 資訊架構（6 頁）

```
new_pancadai/v3/
├── index.html        # 分流首頁：品牌敘事 + 雙軌入口 + 信任帶 + 產品一句話
├── patient.html      # 【患者軌】敘事流：病人的時間軸（scrollytelling 單頁）
├── clinician.html    # 【醫療軌】證據館：臨床數據 × 法規 × 導入方案
├── about.html        # 關於仲智（雙軌共用：技術源頭 + 里程碑 + 團隊）
├── news.html         # 新聞消息（雙軌共用）
├── contact.html      # 聯絡我們（雙軌共用，但表單分流：患者諮詢 / 機構合作）
├── css/style.css     # 全站單一樣式表
├── js/i18n.js        # 三語切換核心（沿用 v2 機制）
├── js/i18n-*.js      # 每頁字典
├── js/main.js        # 動效 + 分流邏輯 + 敘事捲動
└── assets/           # 圖像資產（重用 + 新生成）
```

| 4. 發現 | AI 看見了 1.8cm 的它 | 互動 CT 對比：原始影像 vs AI 標註（**提案 C 元素，體驗型**） | 科技深藍 |

## 5. 設計語言 — 溫暖 × 科技元素分配表（v2 規矩）

| 元素 | 首頁 | 患者軌 | 醫療軌 |
|---|---|---|---|
| 畫布 | 白 + 米白交替 | 白 + 暖色交替 | 深藍漸層 + 白 |
| 主色 | 仲智藍 #295daa + 橘 #ec7000 | 暖橘主導，藍點綴 | 深藍 #0e2244 主導，青 #2a6cc0 點綴 |
| 圖像 | 40 歲生活照 + 全息 AI | 生活照為主，CT 對比穿插 | CT 判讀、證書、圖表 |
| 動效 | 淡入、光暈 | **捲動敘事**（滾動綁定章節） | 數據跑馬燈、掃描線 |
| 字級 | 大標題 | 故事性大標題 | 數據大字報 |
| 情感/證據比重 | 70/30 | 90/10 | 10/90 |

**打破的具體點**：
- 首頁不再是「型錄」，而是「分流點」— 這是台灣醫療 AI 官網罕見的資訊架構
- 患者軌用 **scrollytelling**（捲動=故事）取代靜態區塊
- 醫療軌用 **證據館** 取代感性宣傳 — 放射科主任與採購單位買單的是證據鏈
- 兩軌徹底分離，誰也不稀釋誰

## 6. 技術方案

- 純靜態 HTML/CSS/JS（GitHub Pages / Cloudflare 相容，沿用現行部署）
- 三語 i18n 沿用 v2 機制（data-i18n + PANCAD_LANG + localStorage）
- 敘事捲動：IntersectionObserver + CSS scroll-driven animations（零套件，不用 GSAP）
- CT 互動對比：CSS/SVG 雙圖疊加 + 滑桿（零套件）
- 手機版：幕式捲動退化为章節卡堆疊
