## 0. 家族演進診斷（v2 → v5 繼承什麼、揚棄什麼）

| 版本 | 核心概念 | 標誌資產 | v6 繼承 ✅ / 揚棄 ❌ |
|---|---|---|---|
| v2 | 陽光溫暖 × AI 科技融合 | 語言池背景（en 30 張多元種族 / zh-ja 7 張台灣）、三語 i18n、漸進解析度（small→med→HD）、深耕計畫 zh-only、mflux 生圖流程 | ✅ 三語機制、語言池、深耕規則、漸進載入、生圖管線 |
| v3 | 「一個故事兩個入口」雙軌 | 患者軌 6 幕 scrollytelling、醫療軌證據館、動態光影系統、Intro 進場、互動 CT 滑桿 | ✅ 雙軌 IA、光影系統概念、CT 素材；❌ Intro 擋路 3.2s |
| v4 | 「先體驗，再相信」 | 互動 CT 首屏（split 拖曳/WL/WW/自動演示）、DICOM 視覺語言 | ✅ 互動 CT 語言、DICOM 元素；❌ 附加層疊床架屋 |
| v5 | 「煥然一新」A×B×C | 全息 3D 首屏（CSS 3D 胰臟+星座粒子）、劇場式捲動（kinetic 大字）、手機 App tab bar、暖光三層、92px 數字帶、病人引言、原版 logo、版本號徽章 | ✅ 患者視角首屏、原生捲動+視差、互動 CT、App tab、版本號機制；❌ 特效密度過高（orbs/掃描線/粒子全場常駐）、頁面仍「一頁一區塊」缺乏旅程感、無內容生態 |

**v5 的三大教訓（v6 必須修正）**：
1. **特效多 ≠ 高級**：v5 每個場景都有 orb/掃描線/粒子，密度高但「意義濃度」稀釋。Siemens 的高級感來自**克制**——白/黑/灰紀律、大量留白、真實攝影、每屏一個重點。**v6 = 特效更少但更大、節奏更強、每個動效都承載意義**。
2. **頁面有結構，但敘事沒有「旅程」**：v5 是「往下捲的場景串」，缺少 Siemens 最強的概念——**照護全程（patient journey）**：篩檢→發現→診斷→治療→追蹤。v6 要把它變成**互動旅程地圖**。
3. **證據展示是靜態列表**：92.1%/AUC 0.95 用計數器帶過。v6 要把證據變成**可互動的體驗**（AUC 曲線畫動畫、What-if 生存比較滑桿、AI 判讀模擬）。

## 3. 三個設計提案

### 提案 A「旅程 360°」— 互動照護路徑（Patient Journey as Interface）⭐ 首選

**核心概念：全站以一條可互動的照護旅程為主軸——篩檢 → 發現 → 診斷 → 治療 → 追蹤。** 學習 Siemens 最強概念（全程照護），但做成它做不到的：**捲動即行走**。

```
┌─────────────────────────────────────────────────┐
│  旅程軌（水平路線圖，隨捲動填充亮燈）              │
│                                                   │
│  ①篩檢 → ②發現 → ③診斷 → ④治療 → ⑤追蹤           │
│  （灰點隨捲動逐一亮起，圓環進度動畫）              │
│                                                   │
│  每一站展開 = 一個場景：                           │
│  ①「為什麼早期幾乎無症狀」（教育+情感）            │
│  ②「AI 在 1.2cm 就看見它」（互動 CT + 全息）       │
│  ③「醫師如何確認」（DICOM + 證據）                 │
│  ④「早期治療，存活率翻倍」（What-if 比較）         │
│  ⑤「追蹤與生活」（活出精彩、病人故事）            │
└─────────────────────────────────────────────────┘
```

- **旅程軌**：`position:sticky` 頂部迷你地圖，scroll 進度驅動 5 節點亮燈（CSS 原生，零套件）
- **每站=一個場景**：背景色/光影隨站別切換（暖→科技→信任→希望），動效只服務該站意義
- **②發現站**：升級版互動 CT（v5 split+WL/WW+自動演示）＋全息胰臟（v5 資產）左右並陳
- **④治療站**：**What-if 滑桿**——「1.2cm 發現」vs「晚期發現」存活率比較（基於公開文獻數據，誠實標註來源）
- **⑤追蹤站**：病人引言＋活出精彩生活卡（v5 資產）
- **強項**：直接超越 Siemens 的核心概念；情感×教育×產品體驗一條線
- **弱項**：旅程軌在手機要改垂直設計，需驗證

### 提案 B「證據即體驗」— 互動證據館（Evidence as Experience）⭐ 信任首選

**核心概念：把「為什麼相信我們」變成全站互動體驗，醫療機構決策者 30 秒內拿到答案。**

```
┌─────────────────────────────────────────────────┐
│  首屏：互動 CT 閱片室（v4/v5 升級，5 秒拖出病灶）  │
│  ↓                                                 │
│  AUC 0.95：曲線隨捲動 SVG 畫出 + 面積漸層填色     │
│  ↓                                                 │
│  92.1%（<2cm）：數字從 0 滾到 92.1 + 圖表動畫      │
│  ↓                                                 │
│  FDA Breakthrough / TFDA：時間軸（2019→2026）     │
│  ↓                                                 │
│  認證牆：TFDA/FDA/SNQ/專利/期刊/獎項（卡片 3D）    │
│  ↓                                                 │
│  導入 4 步驟：與醫院系統整合流程                    │
│  ↓                                                 │
│  風險自測 30 秒：互動問答 → 建議篩檢 → 聯絡漏斗   │
└─────────────────────────────────────────────────┘
```

- **AUC 動畫**：純 SVG path `stroke-dashoffset` 隨捲動繪製（零套件）
- **What-if 滑桿**（與 A 共用）：早期 vs 晚期發現的存活敘事
- **風險意識自測**：4-5 題（年齡/家族史/糖尿病史/胰臟炎…）→ 結果頁教育內容 + 醫療機構聯絡 CTA——**Siemens 的聯絡表單我們做成價值先行**
- **強項**：命中醫療機構決策者（v3 雙軌的醫療軌極致化）；數據誠實紅線完全相容
- **弱項**：情感面較弱，需搭配病人故事區塊

### 提案 C「暖光編輯敘事」— 品牌大片（Editorial Premium）

**核心概念：Apple 的克制 × Siemens 的企業紀律 × 我們的暖光——全站「編輯式」設計：白畫布、巨型字、真實攝影、每屏一個重點。** 這是對 v5「特效密度過高」的直接矯正。

- 設計 token：暖白 `#fffaf3` × 深藍 `#0e2244` × 仲智藍 `#295daa` × 橘金 `#ec7000`（僅 CTA/強調），**去 orbs/掃描線/粒子常駐**
- 首屏：全幅真實攝影（40 歲夫妻晨光）+ 巨字 kinetic「早一點發現，多一種可能」
- 每屏一個故事：大字 + 一張圖 + 一句話，捲動節奏像電影分鏡
- 內容生態：衛教知識庫（6-8 篇病人教育文章，內嵌站內）+ 新聞 + FAQ
- **強項**：最高級感、最像 Siemens 但更暖；效能最佳
- **弱項**：與使用者「動態動畫與光影要豐富」偏好需平衡——用「大動效（整屏過場/大字 morph）+ 少小動效」折衷

## 4. 建議組合

| 組合 | 內容 | 適合 |
|---|---|---|
| **A×B** ⭐ | 旅程 360° + 證據即體驗（雙主軸：情感旅程 × 互動證據） | 推薦——Siemens 兩大強項（旅程/信任）我們都做成交互版，且互補（A 情感、B 信任） |
| A×B×C | 全都要（旅程 + 證據 + 編輯式克制設計） | 接受長工期；C 的克制設計語言套用於 A×B 全站 |
| B×C | 證據體驗 + 編輯敘事 | 若想先打醫療機構市場、快上線 |
| C | 純品牌大片 | 最快、最克制，但互動弱 |

**我的推薦：A×B×C 精神，但以 A×B 為骨架、C 的「克制設計語言」為全站底座** ——
也就是：**旅程當主軸、證據做支撐、全站用 Siemens 級克制 × 我們暖光與互動的品牌語彙**。這同時滿足「比 v5 更好」（v5 特效多但散，v6 意義重且精）與「比 Siemens 更好」（它的旅程/信任概念我們做成互動，它有的一切我們加上溫暖、三語、數據）。

## 5. 技術棧（家族傳統：零外部套件）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 捲動 | **原生捲動** + scroll/rAF（家族紅線：lerp 被打回過） | v5 定案，手感第一 |
| 動畫 | CSS + IntersectionObserver + canvas（原生） | 零依賴、比 Siemens 更快 |
| 旅程軌 | CSS sticky + scroll 進度驅動 | 零套件可達 |
| AUC 曲線 | 純 SVG stroke-dashoffset | 零套件 |
| 互動 CT | v4/v5 資產升級（split/WL/WW/自動演示） | 不重造 |
| 全息胰臟 | v5 CSS 3D 分層資產沿用 | 不重造 |
| i18n | v2-v5 三語機制沿用 | 已跑 5 版 |
| 圖像 | mflux（z-image-turbo）＋ SeedVR2 HD（家族管線） | 本地免費 |
| 字型 | 微軟正黑體 / Arial（紅線） | 不變 |
| PWA | manifest + service worker 基本快取 | v5 基礎上加強 |
| 降級 | `prefers-reduced-motion` 全關 | 無障礙紅線 |

**效能目標**：Lighthouse ≥95、LCP < 2.5s（4G）、首屏圖片漸進載入（small→HD）。
