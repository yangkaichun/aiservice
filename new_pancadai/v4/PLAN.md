## 0. 競品研究摘要（6 家，2026-08-11 實抓首頁）

| 網站 | 定位 | 首頁架構（由上而下） | 值得學 | 不學 |
|---|---|---|---|---|

| **Qure.ai**（印，肺結節） | 端到端肺結節照護 | Hero（Image to Intervention）→ 計數器（45M+ 生命/26 FDA）→ 夥伴 logo 牆 → 醫師見證+證據 | 一句話定位（影像→處置）非常銳利 | logo 牆過長（重複 4 次） |

**共通規律（v4 必須遵循）**：① 首屏就要給社會證明（數字或 logo）；② 每個產品區塊只講一個可驗證數字；③ 證據/期刊/法規是基本盤不是加分項；④ CTA 直接對應轉換（Demo 預約、洽詢）；⑤ **所有競品都是「醫療端視角」，沒人好好服務患者** —— v3 的患者軌是稀缺差異化，v4 要強化不是砍掉。

**競品沒人做到的（= v4 的機會）**：把「產品本身」變成首頁主角 —— 沒有一家讓訪客**親手操作** AI 圈病灶。大家都在「說」AI 強，沒人讓你看見。

## 2. 三個設計提案

### 提案 A「產品即首頁」— 互動式 CT 體驗（Product-as-Hero）⭐ 推薦

**核心概念：首屏就是 PANCREASaver 本身。** Hero 不再是一張照片，而是一個真實可操作的 CT 閱片視窗：

```
┌─────────────────────────────────────────────────┐
│  導覽列                                          │
│  ┌──────────────────────────────────────┐       │
│  │  CT 閱片視窗（深色 DICOM 風格）        │       │
│  │  拖曳滑桿：原始影像 ⇄ AI 標註         │       │
│  │  點擊病灶 → 彈出診斷卡               │       │
│  │  [1.2cm 病灶] [92.1% 敏感度]         │       │
│  └──────────────────────────────────────┘       │
│  標題「它 1.2 公分，AI 看見了。」+ 雙 CTA        │
└─────────────────────────────────────────────────┘
```

- **體驗動線**：進站 5 秒內 → 拖一下滑桿 → 看到 AI 圈出肉眼難辨的病灶 → 「這不是投影片，是我自己發現的」→ 信任成立。
- **深色閱片窗 vs 白色網頁的對比** = v4 標誌性視覺語言（全站唯一深色元素，就像真的在看片）。
- **第二屏**：三張「驗證過的事實」卡（92.1% / AUC 0.95 / 300+ 人次），每卡一個數字＋一句話（學 Aidoc 的克制）。
- **第三屏**：雙軌分流卡精簡版（患者故事 / 臨床證據）→ patient.html / clinician.html（v3 兩頁直接繼承升級）。
- **第四屏**：導入流程 4 步（機構）+ 洽詢 CTA。
- **互動技術**：沿用 v3 ct_original.svg/ct_seg.svg 拖曳滑桿，零套件；新增「點病灶看資料卡」；可再加 3 個真實去識別案例（0.9/1.4/1.8cm）做成「病灶瀏覽器」。
- **風險**：CT 素材只有 1 組 → 需要確認是否補生成 2-3 組病灶案例圖；行動版滑桿體驗需簡化為「自動演示」模式。

### 提案 B「證據敘事」— 數字先行的信任工程（Lunit×Gleamer 路線）

**核心概念：一進站就砸數據。** Hero = 標題 + 4 個計數器（92.1% 敏感度 / 0.95 AUC / 300+ 人次 / 10 專利）→ 期刊 logo 牆 → 法規證書 → 雙軌入口 → 導入方案。

- 優點：最貼近國際競品語彙，機構採購者最買單；工程量最小（v3 素材全繼承）。
- 缺點：**沒有新意**——只是把競品模式套上我們的數據；患者情感被壓縮；對家屬訪客不友善。
- 定位：若 v4 主攻「機構招商/投資人」而非品牌全站，此案成立。

### 提案 C「白色畫布 × DICOM 語言」— 極簡電影感（Apple 式）

**核心概念：大幅留白、巨型字排、全站唯一的深色元素是「閱片視窗」的骨架。** 用 CT 介面的 UI 元素（窗寬滑桿、測徑游標、十字線）當作裝飾圖形語言散落全站。

- 優點：設計辨識度最高，與所有醫療 AI 網站（甚至所有台灣生技網站）完全區隔；「醫學專業感」透過介面語言傳達，不是靠照片。
- 缺點：與使用者既有偏好「極致填滿、區塊豐富」相衝（v2/v3 都是資訊密集路線）；大幅留白在 1366px 筆電上可能顯空。
- 折衷：**只把「留白美學」用在首屏與章節過場，內頁維持資訊密集**。

## 3. 建議組合：A × C 混搭「互動式產品首頁」

**為何是 A×C 而不是 A 或 C 單獨**：
- A 提供「新穎的核心體驗」（互動 CT 首屏），C 提供「新穎的視覺語言」（DICOM 介面元素當品牌圖形）——兩者互補：互動視窗需要深色，深色需要白色畫布襯托。
- 保留 v3 雙軌架構 = 保留已被驗證的資訊架構，動線風險最低。
- 台灣市場沒有第二家做「產品即首頁」的醫療 AI，這個差異化對外展出（RSNA/醫療展）也最吸睛。
