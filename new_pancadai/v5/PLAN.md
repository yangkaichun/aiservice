| 版本 | 核心概念 | 標誌資產 | v5 繼承 ✅ / 揚棄 ❌ |
|---|---|---|---|
| v2 | 陽光溫暖 × AI 科技融合 | 語言池背景（en 30 張多元種族 / zh-ja 7 張台灣）、三語 i18n、漸進解析度（small→med→HD）、深耕計畫 zh-only、mflux 生圖流程 | ✅ 三語機制、語言池、深耕規則、漸進載入、生圖流程 |
| v3 | 「一個故事兩個入口」雙軌 | 患者軌 6 幕 scrollytelling、醫療軌證據館、動態光影系統（spot-glow/lightbeam/particles/orbs）、Intro 進場、互動 CT 滑桿 | ✅ 雙軌資訊架構、光影系統概念、CT 素材；❌ Intro 擋路 3.2s、首頁 8 區塊資訊過載 |
| v4 | 「先體驗，再相信」 | 互動 CT 首屏（split 拖曳/WL/WW/自動演示）、DICOM 視覺語言、附加層架構（v3 基底 + v4.css/v4.js） | ✅ 互動 CT 語言、DICOM 裝飾元素；❌ 附加層疊床架屋（v5 要**全新單一樣式**，不再繼承堆疊） |
| 競品/世界級 | Stripe 紫陰影、Framer 純黑畫布、Apple 黑白節奏 + 玻璃導覽 | 54 個真實設計系統（popular-web-designs skill） | ✅ 全數吸收 → 見 §1 |

**v5 的根本姿態**：
1. **不再「繼承檔案、附加覆蓋」** —— v4 的 style.css + v4.css 雙層是歷史包袱。v5 全新 `style.css` 一體成形。
2. **RWD 不是「縮小」，是「重新設計」** —— 手機版是獨立設計的體驗（底部導覽/手勢/App 感），不是桌面版的縮影。
3. **動畫是「捲動驅動」不是「裝飾」** —— 2026 得獎網站共識：動畫服務於敘事節奏，不是點綴。

## 2. 三個設計提案

### 提案 A「全息 3D 首屏」— 沉浸式產品體驗（Product as Experience）⭐ 推薦

**核心概念：首屏就是一個可互動的 3D 全息胰臟模型。** 取代 v4 的平面 CT 視窗，用 CSS 3D + canvas 粒子打造「醫療太空站」感：模型自動旋轉 → 捲動時逐層展開（皮膚→透明網格→血管→病灶閃爍橘光）→ 病灶放大 → AI 標註出現。

```
┌─────────────────────────────────────────────┐
│  導覽列（玻璃）                                │
│  ┌────────────────────┐  ┌──────────────┐   │
│  │  3D 全息胰臟模型     │  │ 標題（kinetic）│   │
│  │  自動旋轉・捲動展開   │  │ 「走進 CT」    │   │
│  │  病灶閃爍・粒子環繞   │  │ 雙 CTA        │   │
│  └────────────────────┘  └──────────────┘   │
│  ↓ 捲動 = 時間軸：展開→偵測→標註→治療→新生    │
└─────────────────────────────────────────────┘
```

- **捲動即敘事**：ScrollTrigger 綁定捲動進度 → 模型變形（scale/rotate/透明度/節點浮現）＋ 場景背景色漸變
- **3D 全息技術**：CSS `transform-style: preserve-3d` 分層卡片（非 WebGL，零套件、手機也順）＋ canvas 粒子環繞（沿用 v3 粒子系統強化）
- **視覺**：深太空藍 `#0a1628` 畫布 × 全息青藍 `#35c4e0` × 仲智橘病灶閃爍 —— 「高科技感」極致
- **第二屏**：v4 互動 CT 閱片視窗精簡版（繼承資產，證明 3D 不是花招、產品真的這樣看片）
- **風險**：3D 效果的「醫療可信度」拿捏——全息是表現手法，旁邊必須緊貼真實 CT 對比（原圖⇄AI），避免淪為科幻遊戲感

### 提案 B「劇場式捲動」— 白畫布 × 大字 × 電影節奏（Apple × Stripe 路線）

**核心概念：Apple 的克制 × Stripe 的質感，全站「場景式」捲動。** 白/淺灰畫布為主、深藍章節穿插（黑白節奏）；每一屏 = 一個場景，標題巨型大字（kinetic reveal）、內容極簡、動畫精準。

- **視覺**：白 `#f8fafc` × 深藍 `#0e2244` 交替、仲智藍 `#295daa` 只用在互動元素（Apple 式單色紀律）、橘 `#ec7000` 只用 CTA
- **動效**：Lenis 平滑捲動 + GSAP 時間軸 + 章節過場（場景切換時背景色滑動漸變）+ 標題逐詞 reveal + 卡片 stagger
- **強項**：最貼近「2026 得獎網站」語彙（By-Kin 式克制）；與品牌既有「暖色資訊密集」最大反差 = 真正的煥然一新
- **弱項**：與使用者「極致填滿」偏好相衝（v2 曾打回留白過多）；需靠「內容仍豐富、版面更精煉」取平衡

### 提案 C「雙模化身」— 桌面沉浸 × 手機 App 原生感（RWD 極致）⭐ RWD 首選

**核心概念：手機不是桌面的縮小版，是「另一個產品」。** 桌面版 = 提案 A 或 B 的沉浸體驗；手機版（<768px）= **App 化介面**：底部 tab 導覽（首頁/患者/醫療/聯絡）、卡片堆疊捲動、手勢滑動（左右滑切換案例）、觸覺式按鈕回饋、PWA 可安裝。

```
桌面（>1024）                   手機（<768）
┌──────────────────┐          ┌──────────┐
│ 沉浸捲動敘事       │          │ 全屏卡片堆疊│
│ 玻璃導覽列         │          │ 手勢左右滑  │
└──────────────────┘          │ 大 CTA 拇指區│
                              ├──────────┤
                              │ [首頁][患者][醫療][聯絡] ← 底部 tab
                              └──────────┘
```

- **技術**：同一份 HTML（SEO 不分裂）+ CSS media query 重排 + JS 偵測觸控（`(pointer:coarse)`）切換互動模式
- **動效**：手機用「輕量優先」——CSS transform/opacity 動畫、`will-change` 精準標記、`prefers-reduced-motion` 全降級；**手機動畫以 60fps 為驗收標準**
- **強項**：直接命中使用者「非常優化的 RWD 網頁設計」要求；醫療網站訪客 60%+ 是手機（家屬查資料多在手機）
- **弱項**：工作量最大（等於做兩套 UX）；需嚴格驗證

## 3. 建議組合

| 組合 | 內容 | 適合 |
|---|---|---|
| **A×C** ⭐ | 3D 全息首屏 + 手機 App 化（雙模） | 若要「高科技感」與「RWD」並重 —— 使用者三項要求全命中 |
| B×C | 劇場式捲動 + 手機 App 化 | 若要「質感/克制」與「RWD」並重 |
| A×B×C | 全都要（工作量最大） | 若接受長工期 |

**我的推薦：A×C** —— 3D 全息是「高科技感」的視覺總爆發，雙模是「RWD 極致」的直接兌現，兩者相輔相成（3D 在手機自動演示、桌面可互動）。

## 4. 技術棧（2026 得獎級但務實）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 平滑捲動 | **Lenis**（CDN，~7KB） | 加權捲動是 2026 得獎標配；零依賴、原生捲動相容 |
| 捲動動畫 | **GSAP + ScrollTrigger**（CDN） | 得獎網站主力；時間軸精準、reduced-motion 降級成熟 |
| 3D 全息 | **CSS 3D + canvas 粒子**（原生） | 醫療網站不需 WebGL 重引擎；手機順暢、零套件 |
| 互動 CT | 繼承 v4 資產與 split 機制（原生） | 已是驗證過的產品；不重造 |
| i18n | 沿用 v2/v3/v4 三語機制 + 字典 | 已跑 4 版、無痛搬移 |
| 圖像 | mflux 生圖流程 + SeedVR2 HD | 家族既有管線 |
| 字型 | 微軟正黑體 / Arial（品牌紅線） | 不變 |
| 降級 | `prefers-reduced-motion` → 全部動畫關閉、平滑捲動停用 | 無障礙紅線 |

**效能目標（手機為準）**：LCP < 2.5s、無 jank（捲動不掉幀）、全站動畫 60fps。
